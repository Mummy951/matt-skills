本文是撰写任何"由 agent 消费的文档"的参考：一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份只能通过指针抵达的文档。它们的封装形式各不相同，写法却是同一套：同样的杠杆能让每一种都变得可预测——因为 agent 每次运行走的是同一套**过程**，而不是产出同一份结果。

如果你正在写的文档是一个 skill，请先读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择和路由型 skill。

## 上下文指针

**上下文指针**是存放在 agent 上下文里的一条引用，它点出某份处于上下文之外的材料，并写明了抵达这份材料的条件。skill 的 description 就是一个上下文指针；`AGENTS.md` 里指出一份文档的那一行，也是同一种东西。决定 agent 何时去取这份材料、取得有多可靠的，是指针的**措辞**，而不是它指向的对象。必备的材料却挂在措辞含糊的指针后面，这是方差缺陷：先把措辞磨利，只有磨不利时才把材料内联进来。

指针做两件事：说明材料是什么，并列出应当触发取用它的**分支**（分支是文档所处理的一种独立情形，不同的运行会因此走不同的路径）。常驻加载的指针，每一个字都在每一轮付费，所以它比正文更值得狠剪：

- **前置引导词**：指针的触发工作就发生在开头。
- **一个分支只配一个触发点。** 给同一个分支换名字的近义词，等于把同一个分支写了两遍；合并它们，只留下真正不同的分支。
- **删掉正文已经交代过的身份介绍。**

## 两种负载

你新增的每一份文档和每一个指针，都要从两种预算中的一种里开销：

- **上下文负载**，是常驻加载的材料压在 agent 窗口上的成本：`AGENTS.md` 的一行、一个 skill 的 description、任何每一轮都待在上下文里的东西。不管它是否被触发，都在消耗 token 和注意力。
- **认知负载**，是压在人身上的成本：有哪些文档、什么时候该用哪一份。人本身就是索引。这项成本不是要压到最低的：它是人的能动性所要付的价钱。该由人判断的地方就花这份成本，不需要人判断的地方就去掉它。

只能通过指针抵达的材料，以指针自己那一行的代价，换来了上下文负载的豁免；完全没有指针的材料，则完全靠认知负载托着。

## 信息层级

一份文档由两类内容构成：**步骤**（agent 按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两类可以自由混合：全是步骤（一份操作配方），全是参考（一份评审的规则、本文这个 skill），或者两者兼有。核心决策是每一块内容在**信息层级**上的位置——这是一条按"agent 对该材料的即时需要程度"排序的阶梯：

1. **文件内步骤**是第一层：agent 要做的事，按顺序排。
2. **文件内参考**，按需查阅。它常常是一组本就平级并列的条目（一份评审的全部规则都放在同一级），这是合理的安排，不是坏味道。
3. **披露式参考**，被推到单独的文件里，靠上下文指针抵达，只在指针触发时才加载。范围从同目录的兄弟文件，一直到存放在任何地方、任何文档都能指向的完全外部参考。

往下推得太少，顶层就会臃肿；推得太多，又会把 agent 真正需要的材料藏起来。这个张力就是全部决策内容。

**渐进披露**就是沿阶梯向下移动（移出主文件、放到指针后面），让顶层保持清晰可读。它首先不是为了省 token，而是保护层级的手段。分支是最干净的披露判据：每条分支都要用的，就内联；只有部分分支会碰到的，就推到指针后面。文档里一旦有步骤，那些本该被披露出去的文件内参考就会把步骤埋掉，让 agent 是否认真对待这些步骤变成抛硬币：这是方差杠杆，不只是可读性问题。

**就近安放**是文件内部的配套做法：阶梯决定一块内容沉到多深，就近安放则决定它落位之后身边放什么。把一个概念的定义、规则和注意事项放在同一个标题下，而不是散在各处，这样读到其中一部分就会把邻近部分一并带进来。检验方法：这份文档读起来应该像是专门写给 agent 的文档。归组的内容读起来就是那样，散落的内容则不是。（这有别于重复：重复是把同一个意思在两处各说一遍；散落是把同一个意思碎成多片撒在各处。）

**蔓延**是这里的失败模式：文档单纯就是太长，哪怕每一行都有效、都不重复。注意力被摊薄在多余内容上，而每多一行，就多一行需要维持相关性。解法就是那条阶梯：把参考披露到指针后面，并按分支或按顺序拆分，让每条路径只携带自己需要的东西。

## 步骤与完成标准

每个步骤都以一个**完成标准**收尾，也就是告诉 agent 工作已经做完的那个条件。两个属性使它成为一个杠杆：

- **清晰度**：agent 能不能分清"做完"和"没做完"？边界含糊（比如"已达成理解"）会招来**提前完成**：步骤还没真做完就收尾，注意力滑向"看起来做完了"。前面还看得见的步骤（**完成后步骤**）提供拉力，完成标准的清晰度提供阻力。按顺序防守：**先磨利边界**（改动局部、代价低）；只有当它本质上无法说清、**而且**你确实观察到抢跑，才通过拆分顺序把后面的步骤藏起来。隐藏只在真正的上下文边界处才有效（交接，或派给子 agent）；如果是内联调用，后面的步骤仍然留在上下文里，什么也没清掉。
- **要求强度**：它要求了多少东西。"每个改动过的模型都要有交代"逼出彻底的工作，而"产出一份变更清单"逼不出来。要求强度驱动**跑腿功夫**（agent 在工作内部所做的挖掘，它藏在措辞里，而不是写成单独一步），并且不局限于步骤："每条规则都执行到位"约束一整套平级参考，正如"每个步骤都做完"约束一个顺序流程——全参考型文档正是靠这个，才依然带着一条穷尽性门槛。

最强的完成标准，既可核对，又穷尽无遗。

## 什么时候该拆

把一份文档拆成两份，要花掉两种负载中的一种，所以只有当这一刀划算时才拆：

- **按顺序拆**：当后面的步骤会诱使 agent 抢跑眼前这一步时，把这一串步骤拆开。让后面的步骤看不见，能推动 agent 在当前任务上多下功夫。反过来也要当心：合并顺序，会把每一步后面的步骤暴露给紧随其后的动作，招来提前完成。
- **按调用方式拆**，这是 skill 专属的做法：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是一个已经活在模型预训练里的紧凑概念，agent 在执行文档时就借助它思考（比如**教训**、**战争迷雾**、**曳光弹**）。它只作为一个词反复出现，从不写成一整句，于是积累出一份分布式定义，用最少的 token 把一整片行为锚定住——靠的是征用模型已有的先验。自己造词也行，前提是你把它定义清楚；但造出来的词征用不到任何先验：预训练词白给的东西，你得用定义 token 去买。所以先伸手去拿现成的词。

它锚定两次。在正文里，锚的是**执行**：词一出现，agent 每次都去取同一套行为；在平级参考里，它把注意力聚焦到某一类该去找的东西上。在指针里，锚的是**调用**：当同一个词同时活在你的 prompt、你的文档和你的代码库里，agent 就会把这套共同语言和那份材料连起来，更可靠地去取用。

主动去找能用引导词重构的地方。一处三件套在三个地方各写一遍，一个指针花一整句话去指向一个想法，每一处都是巴不得缩成一个词的一段话：

- "快、确定、开销低" → **_tight_**（一个 _tight_ 循环）。
- "一条你信得过的循环" → **_red_**，把一个模糊的闸门变成可观测的二值状态（这条循环在该 bug 上是红的，或者不是）。

赢两次：更少的 token，以及一个更锋利的钩子，让 agent 把思考挂在上面。假定每份文档都背着一些可以被引导词取代的重复表述。去找出来。

**否定**是这个杠杆旁边的失败模式：靠禁令来引导，会把被禁的行为拖进上下文，让它变得更容易被调用，而不是更少。"别想大象"，结果满脑子都是大象；否定是个弱修饰，会被被强激活的概念冲垮，于是这条禁令有一半读起来像是在指示"去做那件事"。要提示**正向目标**：直接说出想要的行为（"注释只写一行"），让被禁的那一种从一开始就不必被说出口。禁令只有在作为一种说不出正向表达的硬护栏时才值得留下；即便留下，也要配上一个正向目标，让注意力落在该做什么上。

## 修剪

- 让每个意思只存在于一个**单一事实源**：一处权威位置，这样改行为只需改一处。**重复**（同一个意思出现在不止一处）要花维护成本和 token，还会把某个意思在阶梯上的显眼程度抬到超出它真实的位置。（它恰好是引导词的反面：引导词是故意重复一个词，从不重复意思。）
- **环境**也是一处事实源（`package.json` 的 scripts、配置文件、目录结构、`--help` 的输出）。复述环境的文档是一份**缓存**：一次查询结果的副本，只有当那次查询本身昂贵时，它的负载才划算。要缓存的是 agent 看一眼也查不到的东西：没有写下来的约定、某个选择背后的理由、没有任何配置会承认的坑。一个文件、一条命令就能查到的东西，留给环境本身，放在那儿不会过时。
- 逐行检查**相关性**：这一行是否还和文档要做的事有关？一行失去相关性有两种方式：从来就跟任务无关（纯粹的铺陈，或者一个本该被披露出去的分支），或者它描述的行为、环境变了，它自己过时了。文档越短，越容易保持相关。没有修剪纪律，默认的结局是**沉积**：一层层过时的东西沉下来——因为加显得安全、删显得冒险——直到你得钻穿这些沉积层，才能找到还有效的那部分。
- 逐句猎杀**空操作**：模型本来就默认遵守的指令，花了负载却什么也没说。判据（它相对默认行为是否改变了什么？）是相对于模型的，而不是相对于读者的：两个人对某句话是不是空操作有分歧，其实是他们对默认行为有分歧，解决办法是跑一遍文档，而不是辩论。一句话没通过，就整句删掉，而不是从里面抠掉几个词。这个判据同样用来给引导词打分：一个词太弱、打不过默认（agent 本来就还算仔细时还说"要仔细"）就是空操作，解法是换一个更强的词（"不放过"），而不是换一种技术。
