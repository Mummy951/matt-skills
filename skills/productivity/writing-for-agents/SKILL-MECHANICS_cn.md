# Skill 机制

[`writing-for-agents`](SKILL.md) 的 skill 专属分支：讲的是当文档本身是一个 skill 时，哪些地方会变（frontmatter、调用方式的选择、路由型 skill）。其余所有写法上的内容，都在 `SKILL.md` 那份通用参考里。

## 调用方式

两种选择，各自花掉两种负载中的一种：

- **模型调用型** skill 保留 `description`，agent 能自主触发它，其他 skill 也能取用它。名字照样可以手打调用：模型调用**总是包含**了人的调用通道，description 只往上加"agent 能发现它"这一层，从不会剥掉人那一路。description 是这个 skill 顶层的那条上下文指针，被强制常驻加载：以永久的上下文负载，换可被发现性。内容全是参考的模型调用型 skill，同时也是共享参考的一个落脚点——别的 skill 可以调用它，于是多个 skill 都需要的参考就能只存一份。具体做法：不写 `disable-model-invocation`，并把 description 面向模型来写，带上各个触发分支（`SKILL.md` 里那些指针写法规则，在这里全部适用）。
- **用户调用型** skill 把 description 从 agent 的视野里摘掉：只有人手动输入名字才能调用它，别的 skill 也碰不到它。上下文负载归零，但它花认知负载：你就是那个必须记得它存在的索引。具体做法：设 `disable-model-invocation: true`；`description` 转为面向人——一句话摘要，触发清单全部去掉。

只有当 agent 必须自己够到它、或者别的 skill 必须够到它时，才选模型调用型。如果它永远只靠手打触发，就做成用户调用型，一分上下文负载都不付。

两个用户调用型 skill 都需要的共享参考，谁也放不住：没有 description，谁都触发不了谁。把它推到 skill 体系之外的一个普通文件里，变成任何 skill 都能指向的外部参考。

## 按调用方式拆分

拆分里的"按调用方式切一刀"（按顺序切的那一刀在 `SKILL.md` 里）：当你有一个独立的引导词、该让它自己触发这个 skill（一个你真的会在提示词里用到的触发词），或者别的 skill 必须够到它时，就把这个 skill 拆成模型调用型。新拆出来的 description 是常驻加载的，上下文负载要你出，所以这份"能独立被够到"的好处必须值这个价。

## 路由型 skill

用户调用型 skill 多到你记不住的时候，堆起来的认知负载由**路由型 skill** 来治：一个用户调用型 skill，点名其他 skill，并写明各自什么时候该用，于是人只需要记一个 skill，而不是一堆。它只能给提示，永远不能触发它们：用户调用型 skill 没有 description，除了人，谁都够不到它们。
