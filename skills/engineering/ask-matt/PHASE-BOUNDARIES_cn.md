# 阶段边界

**阶段（phase）** 是会话内的一块工作：深入质询、实现、QA。这个定义刻意保持模糊：当你觉得「好了，这部分我们做完了」，一个阶段就结束了。

**阶段边界** 是两个阶段之间的间隔，也是这个决策唯一该做的位置。阶段中途没有决策可做：继续，或把剩余工作拆给子代理。在阶段中途压缩上下文会让智能体丢失线索。

## 五个选项

| 选项 | 作用 |
| ------------ | --------------------------------------------------------------- |
| **Continue** | 留在当前会话。完全不做上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写出一份可移植的 markdown 文件，并用它在任意位置开启新会话。 |
| **Subagent** | 把任务发到它自己的上下文窗口，并收回一份报告。 |
| **`/compact`** | 压缩当前上下文，用摘要开启一个全新会话。 |

## 决策树

在边界处自上而下处理。第一个 **yes** 胜出。

**1. 你能在当前会话继续吗？** 满足以下两点之一即可回答 yes：下一个阶段需要把本阶段作为**一手资料（primary source）**，或者还留有足够的[智能区（smart zone）](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k tokens）容纳下一个阶段。深入质询 → 实现是标准的 yes：实现需要逐字保留推理过程，而不是它的摘要。继续不付出任何成本、也不损失任何东西，因此在考虑其他选项之前先把它排除掉。

**2. 上下文与接下来的工作无关吗？** 当前会话中的一切（探索、决策、死胡同）是否都可以丢弃？如果是，使用 **`/clear`**。这是棋盘上成本最低的一步：不花时间，还能把整个窗口交回来。`/clear` 也不是终局：旧会话仍然可以恢复。

判断失误的代价是单向的。清空一段**相关**的上下文，你就失去了所做工作背后的**为什么**，再怎么回去读 diff 也找不回来。

**3. 你需要交接吗？** `/handoff` 的适用范围很窄。只有在以下情况才需要它：

- 切换到**新的运行环境（harness）**（Claude → Codex），
- 移动到**新目录**或仓库，
- 把工作交给**同事**，
- 或者在**阶段中途**发现一个附带的支线任务，又不想打断手头正在做的事。

这份清单就是全部条款。`/handoff` 换来的是**可移植性**：一份可以带走的文件。如果没有什么要带走，就不需要它。

**4. 任务可以脱离值守完成吗？** 它的范围是否足够紧凑，可以在你离开键盘、不做任何引导的情况下运行？那就把它发给**子代理**，保持当前会话不动。自动化评审是标准场景：智能体读取 diff 并给出报告，在此过程中不需要你介入。

**5. 否则，使用 `/compact`。** 上下文相关、同一个 harness、同一个目录，而且你需要持续跟进：决策树最终落在这里，而且常常落在这里。给它传一条指令（`/compact we're going to QA this area`），让摘要保留下一阶段所需的内容。

`/compact` 是**默认选项，但不是第一个想到的选项**。它位于底部，是因为上面四个问题对应的选项成本都更低或更精准。从这里开始做决策的失败模式是：开启一个全新会话，却对摘要被抹平的某个决策信心十足地犯错。

## 一手资料与二手资料

除 **Continue** 之外的每一种操作，都会把**一手资料**变成**二手资料**：实际发生的会话被它的摘要取代。这种取舍的形态始终相同：

| 资料 | 信息 | 噪声 | 腾挪空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（Continue） | 完整 | 多 | 小 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 大 |

这就是问题 1 排在最前面的原因。只有当留下来的成本高于它省下的成本时，才承受这种有损损失。

## 这些都是主观判断

这些问题并不客观：每一个都带有主观品味，同一条边界在两天里可能走向不同方向。价值在于**按顺序**提问，并且在边界处提问，而不是在工作中途提问。
